# PIR Review: Replace the Ansari mark with the new logo (prototypes/ansari-expo)

Fixes #223

## Summary

This PR replaces the Ansari mark in `prototypes/ansari-expo` with the new three-piece logo: a diamond at the top, a chevron band in the middle and a wave at the foot. It updates every place the mark is drawn: the sidebar's brass emblem, the sign-in and About headers, the spinning coin on the phone home screen, the loading pulse, and the full set of raster icons. The vector swap is one file, `constants/ansariMark.ts`. The brass effect's numbers were rescaled to the taller viewBox and moved into `constants/brassEmboss.ts`. The icon generator that `index.html` mentioned but that was never committed now exists as `scripts/build-icons.mjs`. It draws the mark with the app's own brass values on the original palm-shadow paper, and it produces byte-identical files on every run.

## Things to Look At During PR Review

- **`constants/brassEmboss.ts` extraction.** `AnsariMarkBrass` now reads every number from this shared module. The extraction doesn't change rendering: re-shooting the 8× emblem and diffing gave a maximum channel delta of 1. The explanatory comments moved with the numbers.
- **`scripts/build-icons.mjs` loads the app's TypeScript under bare Node.** It relies on Node ≥ 22.15 / 24 type stripping and on `module.registerHooks` to stub `react-native`, so `colors.ts` and `ansariMark.ts` load unchanged. If those files ever use TS syntax that can't simply be stripped (`enum`, `namespace`), the script will fail loudly at import.
- **The script repeats the brass SVG stack.** It keeps the same layers as `AnsariMarkBrass` (shadow, edge, body, grain, highlight) but writes them as an SVG string, because the component can't render under Node. The numbers are shared; the layer structure is not. A change to the component's layers needs the same change in the script.
- **`sharp` is a prototype devDependency.** The prototype's `pnpm-lock.yaml` is gitignored, so `package.json` is the only record.
- **Mark proportions.** The new mark is about 17% wider at the same height (aspect 0.88 vs 0.75). Every renderer derives its width from `ANSARI_MARK_ASPECT_RATIO`. In the screenshots, no header is crowded.
- **Native launcher and splash images were not checked on a device.** They only change after a dev-client rebuild.

- **3-way consultation (single pass).** Codex: APPROVE. Claude: APPROVE, with two comment nits, both fixed: `ThinkingLine.tsx` still said star/arcs, and one overlong line in the `index.html` comment.
