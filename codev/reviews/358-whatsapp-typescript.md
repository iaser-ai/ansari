- **Phase 7:** the operator script is Part A of that phase; Part B (staging) is the owner's. The script's unsubscribe safety check matches the token's app by **ID** where Python matched by **name**, and the token is never printed (Python printed a slice of it).

A plan addendum records this. The Python side is done separately (PIR #363) and must match.
- The route is `/whatsapp/v3`, not `/whatsapp/v2`, by owner decision: Meta's callback URL must be changed at cutover.

## Lessons Learned

### What Went Well

- Expected outputs come from running the Python code (fixtures generated by it), so most differences were found by a failing test, not by reading.
- Breaking one rule at a time and watching a test fail (mutation controls) found real gaps in almost every phase, including two in phase 7 (a phone with no id, Ctrl+C).
- A real run against Meta found problems mocks cannot (see below).

### Challenges Encountered

- Several earlier claims of mine were wrong and were corrected when the owner asked for an explanation (phase 5 "signature first" and the JSON error text; recorded in the phase 6 review).
- The local run found: the service listens only on IPv6 (`::1`), so a tunnel to `127.0.0.1` returned 502; Meta's API refuses a verify token over 64 characters while the legacy token is 65; and `dotenv` does not override variables already in the shell, so a shell that had loaded `META_*` made the service use stale values.
- Windows: `curl` treats `[` and `{` in a body as globs; a fake webhook needs an HTTP client and a signature over the exact bytes.

### What Would Be Done Differently

- Run the real-Meta local test earlier, before writing the staging steps, so these findings land in the plan instead of the review.
- Check which port and IP family a tunnel targets before the first request.

### Methodology Improvements

- Porch's `pr_exists` check runs before the PR gate, so the PR must exist before the review phase can close; the SPIR template could say so.
- On native Windows, `afx spawn`, porch's whole-monorepo test check and `consult`'s builder detection each need a local workaround (listed in earlier lessons).

## Lessons Learned Updates

- Routed: cold, `codev/resources/lessons-learned.md`, new section "TypeScript WhatsApp service (issue #358)" — see the lessons below.
  - Meta's `/app/subscriptions` API refuses a `verify_token` over 64 characters; the Graph docs state no limit and the dashboard may accept more. Check length before re-registering a callback by API.
  - `dotenv` never overrides an existing environment variable. A shell that loaded secrets (for example for a read-only Graph call) silently overrides `.env`; start the service from a clean shell.
  - A dev service on `localhost` can bind IPv6 only on Node 22; point a tunnel at `[::1]` or bind `127.0.0.1`.
  - A fake signed webhook is a good local test of the whole chain except delivery: the reply to a BSUID fails on a test number, so only a real message from a phone proves delivery.
- Hot `lessons-critical.md`: no change (capped; none of these is a rule to know before every decision).

## Flaky Tests

No pre-existing tests were skipped. Two flakes were found in this project's own tests and fixed, not skipped:

- A `bad port` fetch error from a blocked port: a test-helper bug, fixed (retries on fetch-blocked ports).
- `tests/backgroundAndServer.test.ts`, `BackgroundTasks > idle() > does not leave its time limit running`: it counted every live timer in the process, so any other timer expiring changed the count. It failed once under turbo's parallel load after the `upstream/develop` merge and never in 8 runs alone. It now checks that the one timer `idle()` starts is cleared, and was shown to fail when `clearTimeout` is removed or aimed at another timer.
