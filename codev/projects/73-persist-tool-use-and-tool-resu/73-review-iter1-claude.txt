## Notes (none blocking)

1. **Deploy ordering is mandatory, not merely preferred.** The PR frames the migration as "additive/nullable — safe ahead of deploy." True, but the converse deserves a louder warning: `toolCallsOrNull()` always returns a value, so the key is always present in the `createMessage` values object, so Drizzle always emits `tool_calls` in the INSERT column list. Deploying *before* the migration would fail **every** assistant-message persist, not just tool-using turns. The PR's step order is correct — I'd just make step 1 explicitly blocking.

  ## Summary
  Restores tool-call persistence lost in the Python→TypeScript rewrite. Every tool dispatch the facilitator makes is now durably recorded — on the assistant row's new nullable `messages.tool_calls` jsonb column, or in a new `tool_call_orphans` table when the turn ended in error/empty and produced no assistant row. No byte of any API response changes: the frozen mobile contract is protected structurally, by explicit read-path projections that omit the column rather than by a serializer that remembers to drop it.

  ## Key Changes
  - **Schema**: `messages.tool_calls` (nullable jsonb) with a fixed status taxonomy (`ok | degraded | budget_skipped | limit_refused | unknown_tool`), plus a separate `tool_call_orphans` table so invisibility to thread GET, share snapshots, history replay, and message counts holds by construction.
  - **Migration** `0007_tool_calls_persistence` (journal idx 6; PR #88 took idx 5) — additive and nullable, generated by `drizzle-kit generate`.
  - **Read-path projections**: `findMessagesByThread` / `getThreadWithMessages` / `createThreadSnapshot` now select explicit column lists that omit `tool_calls` (keeping `raw_payload` for replay), which also avoids a ~7 KB/row detoast per turn.
  - **Facilitator**: a loop-level accumulator records every dispatch path including never-executed ones (T1/T2 budget-skipped with `skip_trigger`, limit-refused, unknown-tool); status is derived from a returned outcome tag plus `isDegraded`, never by string-matching content. Records attach to every terminal event and to `onMessage`.
  - **Routes**: all three persist sites write `tool_calls` on success (`NULL`, never `[]`) and orphan rows on error / empty-final after the client is closed out. `persistOrphanToolCalls` never throws into the stream, never bumps `threads.updated_at`, and logs only `{name, code}`.
