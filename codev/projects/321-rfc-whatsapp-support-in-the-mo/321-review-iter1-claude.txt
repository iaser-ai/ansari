## Issues

**1. (High) Nothing stops `MOCK_AUTH_CLIENT=True` + `MOCK_AUTH_TOKEN` outside `local`.**

`auth_client_mock.py:17-18` returns the *same* JWT for every BSUID when `MOCK_AUTH_TOKEN` is set. All WhatsApp users then collapse into one `apps/api` account and one thread — every user reads and continues every other user's conversation.

This isn't hypothetical: the PR's stated plan is to deploy with the sign-in mocked until `apps/auth` has the route, so `MOCK_AUTH_CLIENT=True` *is* the intended deployed config, and `MOCK_AUTH_TOKEN` is exactly what makes a real `apps/api` accept it. The builder clearly knows the hazard — `conftest.py:19` says "A real token in a developer's .env would make every BSUID the same user" — but that defence lives only in the test fixture, never in `config.py`. A `model_validator` on `WhatsAppSettings` raising when `DEPLOYMENT_TYPE != "local"` and any `MOCK_*` is truthy closes it in ~6 lines, and matches your own hot lesson: *prefer failures that are loud over checks that are quiet*.

**2. (Medium) `_resolve_thread` deletes a thread it never confirmed is a WhatsApp thread.**

`get_last_thread_info` (`ansari_client_real.py:150`) takes `threads[0]` with no `source` filter, and `_resolve_thread` deletes it on expiry. `create_thread` tags `source: "whatsapp"`, and `GET /api/v2/threads` already returns `source`. Safe today because BSUID accounts hold only whatsapp threads — but the moment the real `/whatsapp` route maps a BSUID onto an account that also has web threads, a WhatsApp message 3 hours later silently deletes the user's web thread *and its messages*. The follow-up list already describes the sweep as "keep each user's newest `whatsapp` thread," so filtering is the intended semantics anyway.

**3. (Medium) `e.response.text` is logged raw, against a documented guarantee.**

`meta_api_service_real.py:66` and `:143` log Meta's raw error body. `README.md:100` states unconditionally: "Logs deliberately contain no phone numbers, BSUIDs or message text." Meta's send-failure bodies can echo the recipient. Either reduce to `{name, code}` (your hot lesson on raw error objects) or qualify the README claim — right now the doc asserts something the code doesn't enforce.

**4. (Low) Dead debug block.** `ansari_client_real.py:221-237` — a commented-out "TEMPORARY: Save response to file" block. Straight "no debug code" PR-readiness item; not mentioned in the review doc.
