**3. The new Sentry captures have no test.** No test file references `capture_exception`, `_capture`, or Sentry at all. The Phase 4 plan lists adding Sentry to the thread-list/create/delete failures as this phase's work, so the one piece of new behaviour added here is the one piece with no coverage. Reading the code, I'm confident the calls are correct — my point is only that nothing would notice if they vanished.

**4. The `httpx.TimeoutException` branch in `handle_text_message` is unreachable.** `AnsariClientReal.process_message` catches `httpx.TimeoutException` at line 240 and re-raises it as `MessageProcessingError`; `AnsariClientMock` never raises it either (its only raises are `ThreadDeletionError`/`MessageProcessingError`). So `whatsapp_conversation_manager.py:284-291` — the `backend_timeout` Sentry tag and the "The request timed out" user message — can't fire. Practical effect is cosmetic (a timeout tells the user "An error occurred" and is tagged `message_processing_failure`), but the plan's Phase 4 outcome note claims "timeout … failures are captured in Sentry" as a distinct case, and it isn't. Either let the real client re-raise timeouts unwrapped, or drop the branch and the claim.

**5. `test_json_logs_are_off_in_local_development_and_in_ci` (`test_railway_logging.py:74-77`) is vacuous for half its name.** `use_json_logs` is `DEPLOYMENT_TYPE not in [local, development] and GITHUB_ACTIONS != "true"`, and conftest pins `DEPLOYMENT_TYPE=local`. The assertion passes identically whether or not the `GITHUB_ACTIONS` clause exists — delete that clause and the test still goes green. If the CI guard matters, test it by building the expression with a staging deployment type and `GITHUB_ACTIONS=true`.

**6. Python version drift between CI, dev and the image.** There is no `.python-version` in `apps/whatsapp` and `requires-python = ">=3.10"`, so CI's `uv sync` installs the newest compatible CPython while the Dockerfile runs `python:3.13` and this worktree's venv is 3.10.10 (I confirmed all three). CI can go green on a version that never ships. A `.python-version` pinned to 3.13 (and `setup-uv` reading it) closes that.

**7. `.env.example` still documents a file that wasn't imported.** Lines 97-102 define `META_WABA_ID` "for `check_subscriptions.py` only" — that script doesn't exist in `apps/whatsapp`, and `META_WABA_ID` isn't a field in `config.py` (so `extra="ignore"` silently drops it). Delete it or say it's vestigial. Minor companion: `ORIGINS` on line 32 still carries an `ngrok` host from the legacy setup.

**8. Ordering nit, no fix required:** the maintenance check (`main.py:337`) precedes the `!d ` filter (`main.py:354`), so a staging instance in maintenance mode replies to a local developer's `!d ` message with the maintenance notice — the exact double-answer the prefix exists to prevent.
