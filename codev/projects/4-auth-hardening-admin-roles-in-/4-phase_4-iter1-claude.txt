## Follow-ups (none block the phase)

1. **`docs/self-hosting.md:66` is now factually wrong and operationally dangerous.** It still reads "Comma-separated allowlist for the admin dashboard." Post-phase-4, `ADMIN_EMAILS` grants nothing — it reserves + asserts — and a non-empty value makes production boot depend on a flagged DB row. A self-hoster upgrading with a value set gets a fully-500ing deploy and no explanation. The diff contains no docs changes. This is on the plan's pre-PR "Documentation Updates Required" list (`.env.example`, self-hosting table, runbook ordering migration → `grant-admin.ts` → deploy) — just don't let it slip past Phase 9.

2. **`isReservedAddress` requires pre-normalized input** and returns `false` for `Admin@Ansari.Chat` (tested as the contract at `reserved.test.ts:28`). Only one caller today and it lowercases — but Phase 5 adds a domain check and more surface. Normalizing inside the helper (`email.trim().toLowerCase()`) costs one line and removes a bypass-by-forgetting footgun.

3. **Transient-DB boot coupling** (spec Notes asked the plan to address this; empirically confirmed above): with `ADMIN_EMAILS` set, a DB blip at boot bricks the instance into permanent 500s with no retry, even when admins are correctly provisioned. Railway's `restartPolicyMaxRetries = 3` plus healthcheck contains the blast radius, so this is acceptable as-is — but consider distinguishing a connection error (retry/clearer message) from "admin missing," or at minimum record the observed failure mode in the runbook so an on-call sees `Failed to prepare server` and knows where to look.

4. **`grantAdmin` enforces only a 12-char minimum**, bypassing `checkPasswordStrength`. Phase 9 raises the app policy to `score >= 3`, so the highest-privilege account in the system would be the one allowed to use `aaaaaaaaaaaa`. Reusing the existing strength check in the script is nearly free.

5. Minor: `tsconfig.json` excludes `scripts/**`, so `npm run typecheck` doesn't cover `grant-admin.ts` — it's covered by `grant-admin.test.ts` instead. Pre-existing repo convention; no action needed, just be aware the script has no static safety net.
