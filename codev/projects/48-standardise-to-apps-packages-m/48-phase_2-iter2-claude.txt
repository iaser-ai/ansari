## Comments (none blocking)

1. **`typecheck` + `build` race inside `ansari-api` when run in one turbo invocation.** My first run of the plan's own acceptance command failed after ~3s with `ansari-api#typecheck … exited (2)` and `build` at 130; the identical command passed on re-run. Cause: `apps/api/tsconfig.json:24` includes `.next/types/**/*.ts`, which a concurrent `next build` rewrites underneath `tsc`. CI is unaffected (separate sequential steps), and it's not introduced by this phase's config per se — but Phase 6 re-runs exactly this combined command, so **flag it now** rather than have a flake there get papered over or mis-diagnosed. Options: keep the acceptance command but run typecheck separately, or note the race in `turbo.json`.
2. **`_comment_build:web` lives inside `"scripts"`** (`apps/frontend/package.json:12`). It becomes a listed, "runnable" script whose body is an English sentence. The same note already exists in `turbo.json:122-125`; a top-level `"//"` key would keep it out of the script namespace.
3. **`gen:types` inputs are narrowed** to `["src/global.css", "package.json"]` with no `$TURBO_DEFAULT$`. Correct today (the dts derives only from the themes declaration, and `global.css`'s only `@source` points into `node_modules`, covered by the `pnpm-lock.yaml` global dependency). It becomes stale-silent the day someone adds a local `@import`/`@source` — worth a one-line caveat next to the task.
4. **`docs/self-hosting.md` is in the plan's phase-2 file list but was not touched in this phase.** Its command blocks stayed app-scoped, which is defensible and consistent with the recorded RELEASE.md decision — but I couldn't find that rationale written down anywhere. One line in the PR notes closes the "silently skipped plan item" question.
5. **Frontend job name `frontend (lint, typecheck)` now also builds.** The comment explains the freeze, and it's the safe default; noting only that this check isn't protection-required, so it's the one name that *could* be corrected without an admin change.
