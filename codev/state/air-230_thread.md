# air-230 — theme-adaptive SVG favicon

## Implement
- `public/favicon.svg` is generated by `scripts/build-icons.mjs` (`themedFaviconSvg`) from
  `ANSARI_MARK_SHAPES` + the issue's fixed hex inks (#2B2422 / #E8E4E3). Re-running
  `pnpm build:icons` leaves every existing raster byte-identical.
- **Surprise:** adding the SVG link alone did nothing in Chrome. The existing
  `<link rel="icon" href="/favicon.ico" sizes="any">` outranks an SVG. Declaring the
  .ico's true list (`16x16 32x32 48x48`) also loses, and so does `sizes="any"` on the
  SVG. Only `.ico sizes="32x32"` + SVG with no `sizes` makes Chrome pick the SVG.
- How verified without the Chrome extension or screen access: launch a throwaway
  headful Chrome profile, then read `<profile>/Default/Favicons` (SQLite,
  `favicons ⨝ favicon_bitmaps`) to see which icon URL Chrome stored. Control: an
  SVG-only page records the SVG, so the signal is real.
- Live ink: headless CDP `Emulation.setEmulatedMedia` flipped light→dark→light on one
  open SVG document; the computed fill tracks both inks exactly and the ground stays transparent.
- Not verified: the real tab strip repainting on an OS theme flip (no screen capture
  permission). It rests on browser behavior plus the CDP check above.
