# Research: Thread Lifecycle in API Layer

**Date**: 2026-11-22
**Task**: 1.4
**Status**: In Progress

## Objective

Research how to move thread lifecycle management from the WhatsApp layer to the API layer, including thread creation, reuse, expiry, and cleanup.

## Background

Currently, the WhatsApp service manages thread lifecycle:
- One thread per user
- Thread replaced after 3 hours of inactivity (configurable via `WHATSAPP_CHAT_RETENTION_HOURS`)
- Thread expiry logic in `apps/whatsapp/src/conversationManager.ts`

The spec requires moving this logic to the API layer so that:
- The API endpoint handles thread creation/reuse internally
- Thread expiry is user-configurable (0-24 hours, default 3 hours)
- The WhatsApp layer just calls the API endpoint

## Current Implementation

### WhatsApp Layer (Current)

**File**: `apps/whatsapp/src/conversationManager.ts`

**Logic**:
1. Check if user has a thread with `source='whatsapp'`
2. If last message > expiry time ago, delete old thread and create new
3. Otherwise reuse existing thread
4. Pass thread ID to API calls

**Thread Expiry**:
- Global setting: `WHATSAPP_CHAT_RETENTION_HOURS` (default 3 hours)
- Checked on each message
- Thread deleted if expired

### API Layer (Current)

**File**: `apps/api/lib/db/threads.ts`

**Current Behavior**:
- Thread CRUD operations
- No expiry logic
- Thread ID passed from client

## Proposed Changes

### API Layer (New)

**New Endpoint**: `POST /api/v2/chat/complete`

**Request**:
```json
{
  "message": "What does the Quran say about patience?",
  "expiryHours": 3
}
```

**Thread Lifecycle Logic**:
1. Extract user ID from JWT
2. Check if user has an active thread (source='whatsapp')
3. If no thread or thread expired, create new thread
4. If thread exists and not expired, reuse it
5. Run AI model with thread context
6. Update thread's last message time
7. Return response

**Thread Expiry**:
- User-configurable: `expiryHours` in request (0-24 hours)
- 0 = new thread per message
- Default: 3 hours
- Checked on each request

## Design Decisions

### 1. Thread Identification

**Current**: Thread ID passed from WhatsApp layer
**New**: Thread identified by user ID + source

**Query**:
```sql
SELECT * FROM threads 
WHERE user_id = $1 
  AND source = 'whatsapp' 
  AND last_message_at > NOW() - INTERVAL '$2 hours'
ORDER BY created_at DESC 
LIMIT 1
```

### 2. Thread Creation

**When to create**:
- No existing thread for user
- Existing thread expired
- `expiryHours = 0` (new thread per message)

**Thread Data**:
```json
{
  "user_id": "uuid",
  "source": "whatsapp",
  "created_at": "timestamp",
  "last_message_at": "timestamp"
}
```

### 3. Thread Expiry Check

**When to check**:
- At the start of each request
- Before creating a new thread

**Logic**:
```typescript
function isThreadExpired(thread: Thread, expiryHours: number): boolean {
  if (expiryHours === 0) return true; // Always create new thread
  const expiryTime = new Date(thread.lastMessageAt);
  expiryTime.setHours(expiryTime.getHours() + expiryHours);
  return new Date() > expiryTime;
}
```

### 4. Thread Cleanup

**When to cleanup**:
- When creating a new thread (delete old one)
- Periodic cleanup job (optional)

**Logic**:
```typescript
async function cleanupExpiredThreads(expiryHours: number): Promise<void> {
  await db.delete(threads)
    .where(
      and(
        eq(threads.source, 'whatsapp'),
        lt(threads.lastMessageAt, new Date(Date.now() - expiryHours * 60 * 60 * 1000))
      )
    );
}
```

### 5. Race Conditions

**Problem**: Multiple concurrent messages from same user
**Solution**: Use database transaction with row-level locking

**Implementation**:
```typescript
async function getOrCreateThread(userId: string, expiryHours: number): Promise<Thread> {
  return await db.transaction(async (tx) => {
    // Lock the user's thread row
    const [thread] = await tx.select()
      .from(threads)
      .where(and(eq(threads.userId, userId), eq(threads.source, 'whatsapp')))
      .for('update');
    
    if (thread && !isThreadExpired(thread, expiryHours)) {
      return thread;
    }
    
    // Delete expired thread
    if (thread) {
      await tx.delete(threads).where(eq(threads.id, thread.id));
    }
    
    // Create new thread
    const [newThread] = await tx.insert(threads)
      .values({
        userId,
        source: 'whatsapp',
        createdAt: new Date(),
        lastMessageAt: new Date(),
      })
      .returning();
    
    return newThread;
  });
}
```

## Edge Cases

### 1. Concurrent Messages
- **Problem**: User sends multiple messages quickly
- **Solution**: Database transaction with row-level locking
- **Test**: Send 10 messages simultaneously

### 2. Thread Expiry During Request
- **Problem**: Thread expires while request is processing
- **Solution**: Check expiry at start, use thread for entire request
- **Test**: Set short expiry time, send message

### 3. Database Failures
- **Problem**: Database down or slow
- **Solution**: Return error, let WhatsApp layer retry
- **Test**: Simulate database failure

### 4. Network Failures
- **Problem**: Network issues between WhatsApp and API
- **Solution**: Return error, let WhatsApp layer retry
- **Test**: Simulate network failure

### 5. Invalid Expiry Hours
- **Problem**: User sends invalid expiryHours (e.g., -1, 25)
- **Solution**: Validate input, use default (3 hours)
- **Test**: Send invalid expiryHours
