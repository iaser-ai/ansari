**Date**: 2026-11-22
**Task**: 1.1

## Objective

Analyze what makes up the final response message in the streaming scenario and determine how each component should be formatted for WhatsApp's limited markdown.

## Current Streaming Response Components

Based on the existing codebase analysis:

### 1. Text Content
- **Source**: `apps/api/lib/facilitator/agent.ts` - the facilitator generates text responses
- **Format**: Markdown with standard syntax (`**bold**`, `*italic*`, `~~strikethrough~~`, `` `code` ``)
- **WhatsApp conversion needed**: 
  - `**bold**` → `*bold*`
  - `*italic*` → `_italic_`
  - `~~strikethrough~~` → `~strikethrough~`
  - `` `code` `` → `` `code` `` (same)
  - `# Headings` → `*Heading*` (bold)
  - Lists: `- item` → `• item` (bullet)

### 2. Citations/Footnotes
- **Source**: Tool call results from Quran/Hadith search
- **Format**: Currently in markdown footnotes or inline references
- **WhatsApp format**: Inline text with source attribution
- **Example**: `"The Quran says in verse 2:153..."` → `*The Quran says in verse 2:153...*`

### 3. Quran/Hadith References
- **Source**: Tool call results from search
- **Format**: Arabic text + English translation + reference
- **WhatsApp format**: 
  - Arabic text: Keep as-is (RTL support)
  - Translation: Italic or quoted
  - Reference: Bold or monospace
- **Example**: 
  ```
  *Quran 2:153* (Al-Baqarah)
  "O you who have believed, seek help through patience and prayer..."
  ```

### 4. Tool Call Results
- **Source**: Search results from Quran/Hadith databases
- **Format**: Structured data (JSON from tool calls)
- **WhatsApp format**: Convert to readable text
- **Example**: 
  ```
  *Search Results:*
  • Quran 2:153 - Al-Baqarah
  • Quran 3:200 - Ali 'Imran
  ```

### 5. Code Blocks
- **Source**: If AI generates code examples
- **Format**: Markdown code blocks (```code```)
- **WhatsApp format**: Monospace with backticks (`` `code` ``)
- **Note**: WhatsApp doesn't support multi-line code blocks well; may need to split or use inline code

### 6. Lists
- **Source**: AI-generated lists
- **Format**: Markdown lists (`- item`, `1. item`)
- **WhatsApp format**: 
  - Unordered: `• item`
  - Ordered: `1. item` (keep numbers)

### 7. Links/URLs
- **Source**: AI-generated or tool call results
- **Format**: Markdown links (`[text](url)`)
- **WhatsApp format**: Just the URL (auto-linked)
- **Example**: `https://example.com` → `https://example.com`

## WhatsApp Formatting Constraints

From Meta's WhatsApp Business API documentation:

### Supported Formatting:
- **Bold**: `*text*`
- **Italic**: `_text_`
- **Strikethrough**: `~text~`
- **Monospace**: `` `text` ``
- **Code blocks**: `` ```text``` `` (limited support)
- **Quotes**: `> text`
- **Bullet lists**: `• text` or `- text`
- **Numbered lists**: `1. text`

### Unsupported:
- **Headings**: No `# ## ###` syntax
- **Tables**: No table support
- **Nested formatting**: Limited (e.g., bold inside italic may not work)
- **Links**: No `[text](url)` syntax; URLs are auto-linked
- **Images**: Not supported in text messages
- **Complex layouts**: No multi-column, no advanced styling

### Character Limits:
- **Max message length**: 4,096 characters
- **Recommended**: Split at paragraph/sentence boundaries
- **Continuation markers**: Add " (1/3)" to indicate message parts

### 1.1.2 Research WhatsApp Business API Formatting

**Findings from web research:**

#### Supported Formatting (WhatsApp Business API):
- **Bold**: `*text*` (asterisks)
- **Italic**: `_text_` (underscores)
- **Strikethrough**: `~text~` (tildes)
- **Monospace**: `` `text` `` (single backticks) or ```` ```text``` ```` (triple backticks)
- **Bullet lists**: `• text` or `- text`
- **Numbered lists**: `1. text`
- **Block quotes**: `> text`
- **Emojis**: Full support
- **Line breaks**: `\n` supported

#### Unsupported Formatting:
- **Headings**: No `# ## ###` syntax
- **Tables**: No table support
- **Nested formatting**: Limited (e.g., bold inside italic may not work reliably)
- **Links**: No `[text](url)` syntax; URLs are auto-linked
- **Images**: Not supported in text messages
- **Advanced styling**: No multi-column, no custom fonts

#### Character Limits:
- **Text messages**: 4,096 characters maximum
- **Template messages**: 1,024 characters maximum
- **Interactive messages**: 1,024 characters body, 60 characters header/footer
- **Recommended**: Split at paragraph/sentence boundaries for readability

#### Best Practices:
1. **Keep messages concise**: 3-4 sentences per message for most responses
2. **Use formatted lists**: Break complex information into bullet points
3. **Add spacing**: Leave blank lines between distinct thoughts
4. **Limit list items**: 5 items maximum per message
5. **Split long content**: Use continuation markers like " (1/3)"
6. **Test formatting**: WhatsApp rendering can vary by device/platform

#### Sources:
- Meta WhatsApp Business API documentation
- Multiple WhatsApp BSP (Business Solution Provider) docs
- WhatsApp API SDK documentation

### 1.1.3 Analyze Tool Call Results Format

**Findings from codebase analysis:**

#### Tool Result Structure:
```typescript
interface ToolResult {
  content: string;           // Human-readable summary
  documents: DocumentBlock[]; // Structured data for citations
  isDegraded?: boolean;      // Error/degradation flag
  degradation?: ToolDegradation; // Error details
}

interface DocumentBlock {
  type: 'document';
  source: {
    type: 'text';
    media_type: 'text/plain';
    data: string;            // JSON string with actual content
  };
  title: string;             // Citation title (e.g., "Quran 2:255")
  context?: string;          // Additional context
  citations?: {
    enabled: boolean;        // Whether this can be cited
  };
}
```

#### Example: Quran Search Result
```json
{
  "content": "Please see the Quran verses below.",
  "documents": [
    {
      "type": "document",
      "source": {
        "type": "text",
        "media_type": "text/plain",
        "data": "{\"ar\":\"بِسْمِ اللَّهِ الرَّحْمَٰنِ الرَّحِيمِ\",\"en\":\"In the name of Allah, the Entirely Merciful, the Especially Merciful.\"}"
      },
      "title": "Quran 1:1",
      "context": "Retrieved from the Holy Quran",
      "citations": { "enabled": true }
    }
  ]
}
```

#### WhatsApp Formatting Needed:
```
*Quran 1:1* (Al-Fatihah)
"بِسْمِ اللَّهِ الرَّحْمَٰنِ الرَّحِيمِ"
"In the name of Allah, the Entirely Merciful, the Especially Merciful."
```

#### Tool Call Types:
1. **search_quran**: Returns Quran verses with Arabic + English
2. **search_hadith**: Returns Hadith with Arabic + English + narrator
3. **search_tafsir**: Returns Tafsir (Quranic exegesis) with Arabic + English
4. **search_mawsuah**: Returns Islamic encyclopedia articles

#### Conversion Strategy:
1. **Parse `documents` array**: Extract title, Arabic text, English text
2. **Format for WhatsApp**:
   - Title: `*Title*` (bold)
   - Arabic: Keep as-is (RTL support)
   - English: Italic or quoted
   - Context: Regular text
3. **Handle multiple results**: Number them or bullet them
4. **Handle degraded results**: Show error message in WhatsApp format

#### Edge Cases:
- **No results**: Return "No results found" message
- **Degraded tool**: Return "temporarily unavailable" message
- **Arabic text**: Ensure proper RTL rendering
- **Long text**: Split at sentence boundaries
- **Special characters**: Escape properly for WhatsApp

- **Challenge**: WhatsApp has 4096 char limit per message
- **Solution**: Split at sentence boundaries, add continuation markers

#### 10. Very Long Tool Results

## Findings

### Current WhatsApp Formatter Analysis

The existing `whatsappMessageFormatter.ts` in `apps/whatsapp` already handles:
- Basic markdown to WhatsApp conversion
- Bold, italic, strikethrough, monospace
- List conversion
- Link handling

**Key insight**: The formatter is already working in the WhatsApp service. The question is whether to:
1. **Move it to API layer** (as per spec) - requires duplicating logic or creating shared package
2. **Keep it in WhatsApp layer** - simpler, but spec says API should return WhatsApp-formatted text

**Recommendation**: Move the formatter to API layer as a shared utility that both streaming and non-streaming endpoints can use. This ensures consistency.

### Tool Call Results

Tool calls return structured data:
```json
{
  "tool": "search_quran",
  "results": [
    {
      "surah": 2,
      "ayah": 153,
      "text_arabic": "يَا أَيُّهَا الَّذِينَ آمَنُوا اسْتَعِينُوا بِالصَّبْرِ وَالصَّلَاةِ...",
      "text_english": "O you who have believed, seek help through patience and prayer...",
      "reference": "Al-Baqarah 2:153"
    }
  ]
}
```

**WhatsApp format needed**:
```
*Quran 2:153* (Al-Baqarah)
"يَا أَيُّهَا الَّذِينَ آمَنُوا اسْتَعِينُوا بِالصَّبْرِ وَالصَّلَاةِ..."
"O you who have believed, seek help through patience and prayer..."
```

### Arabic Text Handling

Arabic text requires:
- RTL (Right-to-Left) support
- Proper character encoding (UTF-8)
- No special formatting that breaks RTL
- Test with WhatsApp to ensure proper display
