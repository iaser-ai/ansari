# Research: Smart Text Splitting

**Date**: 2026-11-22
**Task**: 1.3
**Status**: In Progress

## Objective

Research libraries and approaches for splitting text at paragraph/sentence boundaries to fit WhatsApp's 4096 character limit per message, and evaluate which approach is best for our use case.

## Background

WhatsApp has a 4096 character limit per message. When the AI generates a response longer than this, we need to split it into multiple messages at logical boundaries (paragraphs, sentences) rather than hard character cuts.

## Requirements

1. **Split at paragraph boundaries**: Prefer splitting between paragraphs
2. **Split at sentence boundaries**: If paragraphs are too long, split between sentences
3. **Respect formatting**: Don't break markdown formatting (e.g., bold text, lists)
4. **Add continuation markers**: Indicate message parts (e.g., " (1/3)")
5. **Handle edge cases**: Long paragraphs, code blocks, lists, Arabic text
6. **Performance**: Fast and efficient
7. **Dependencies**: Minimize new dependencies if possible

## Libraries/Approaches

### Option 1: `llm-chunk`

**Description**: A simple, fast library for splitting text at paragraph/sentence boundaries.

**Installation**:
```bash
npm install llm-chunk
```

**Usage**:
```typescript
import { chunkText } from 'llm-chunk';

const chunks = chunkText(longText, {
  maxLength: 4096,
  separator: '\n\n', // Split by paragraphs first
});
```

**Pros**:
- Simple API
- Fast
- Lightweight
- Respects paragraph boundaries
- Good for most cases

**Cons**:
- Limited customization
- May not handle all edge cases
- No built-in continuation markers

**Example**:
```typescript
const text = "Paragraph 1...\n\nParagraph 2...\n\nParagraph 3...";
const chunks = chunkText(text, { maxLength: 4096 });
// Returns: ["Paragraph 1...\n\nParagraph 2...", "Paragraph 3..."]
```

### Option 2: LangChain's `RecursiveCharacterTextSplitter`

**Description**: A more sophisticated text splitter from LangChain that splits by paragraphs → sentences → words.

**Installation**:
```bash
npm install langchain
```

**Usage**:
```typescript
import { RecursiveCharacterTextSplitter } from 'langchain/text_splitter';

const splitter = new RecursiveCharacterTextSplitter({
  chunkSize: 4096,
  chunkOverlap: 0, // No overlap for WhatsApp
  separators: ['\n\n', '\n', '. ', ' '], // Split by paragraphs, then lines, then sentences, then words
});

const chunks = await splitter.splitText(longText);
```

**Pros**:
- Very sophisticated
- Respects multiple boundary types
- Handles edge cases well
- Widely used and tested

**Cons**:
- Heavy dependency (LangChain)
- Slower than simpler libraries
- May be overkill for our needs
- Adds significant bundle size

**Example**:
```typescript
const text = "Paragraph 1...\n\nParagraph 2...\n\nParagraph 3...";
const chunks = await splitter.splitText(text);
// Returns: ["Paragraph 1...", "Paragraph 2...", "Paragraph 3..."]
```

### Option 4: Custom Regex-Based Splitting

**Description**: Implement our own splitting logic using regex.

**Implementation**:
```typescript
function splitText(text: string, maxLength: number): string[] {
  const paragraphs = text.split('\n\n');
  const chunks: string[] = [];
  let currentChunk = '';

  for (const paragraph of paragraphs) {
    if ((currentChunk + paragraph).length <= maxLength) {
      currentChunk += (currentChunk ? '\n\n' : '') + paragraph;
    } else {
      if (currentChunk) {
        chunks.push(currentChunk);
      }
      currentChunk = paragraph;
    }
  }

  if (currentChunk) {
    chunks.push(currentChunk);
  }

  return chunks;
}
```

**Pros**:
- No dependencies
- Full control
- Easy to customize
- Lightweight

**Cons**:
- Need to handle edge cases ourselves
- May not be as robust as libraries
- Need to test thoroughly

**Example**:
```typescript
const text = "Paragraph 1...\n\nParagraph 2...\n\nParagraph 3...";
const chunks = splitText(text, 4096);
// Returns: ["Paragraph 1...\n\nParagraph 2...", "Paragraph 3..."]
```

### Option 5: Hybrid Approach (Paragraph → Sentence → Word)

**Description**: Implement a multi-level splitting strategy: try paragraphs first, then sentences, then words.

**Implementation**:
```typescript
function splitText(text: string, maxLength: number): string[] {
  // Try paragraphs first
  let chunks = splitByParagraph(text, maxLength);
  
  // If any chunk is still too long, split by sentence
  chunks = chunks.flatMap(chunk => 
    chunk.length > maxLength ? splitBySentence(chunk, maxLength) : [chunk]
  );
  
  // If any chunk is still too long, split by word
  chunks = chunks.flatMap(chunk => 
    chunk.length > maxLength ? splitByWord(chunk, maxLength) : [chunk]
  );
  
  return chunks;
}

function splitByParagraph(text: string, maxLength: number): string[] {
  const paragraphs = text.split('\n\n');
  return splitBySeparator(paragraphs, maxLength, '\n\n');
}

function splitBySentence(text: string, maxLength: number): string[] {
  const sentences = text.match(/[^.!?]+[.!?]+/g) || [text];
  return splitBySeparator(sentences, maxLength, ' ');
}

function splitByWord(text: string, maxLength: number): string[] {
  const words = text.split(' ');
  return splitBySeparator(words, maxLength, ' ');
}

function splitBySeparator(items: string[], maxLength: number, separator: string): string[] {
  const chunks: string[] = [];
  let currentChunk = '';

  for (const item of items) {
    const testChunk = currentChunk + (currentChunk ? separator : '') + item;
    if (testChunk.length <= maxLength) {
      currentChunk = testChunk;
    } else {
      if (currentChunk) {
        chunks.push(currentChunk);
      }
      currentChunk = item;
    }
  }

  if (currentChunk) {
    chunks.push(currentChunk);
  }

  return chunks;
}
```

**Pros**:
- No dependencies
- Full control
- Handles edge cases well
- Robust

**Cons**:
- More complex implementation
- Need to test thoroughly
- May be slower than libraries

**Example**:
```typescript
const text = "Long paragraph with many sentences. Another sentence here. And another one.";
const chunks = splitText(text, 50);
// Returns: ["Long paragraph with many sentences.", "Another sentence here.", "And another one."]
```

## Edge Cases to Handle

### 1. Long Paragraphs
- **Problem**: A single paragraph > 4096 chars
- **Solution**: Split by sentence, then by word if needed

### 2. Code Blocks
- **Problem**: Code blocks should not be split
- **Solution**: Detect code blocks and keep them intact, or split with clear markers

### 3. Lists
- **Problem**: Lists should not be split mid-item
- **Solution**: Detect lists and keep items intact

### 4. Arabic Text
- **Problem**: Arabic text may have different sentence boundaries
- **Solution**: Use proper Unicode sentence detection

### 5. Nested Formatting
- **Problem**: Formatting may break across chunks
- **Solution**: Ensure formatting is preserved or flattened

### 6. Continuation Markers
- **Problem**: Need to add " (1/3)" to each chunk
- **Solution**: Add markers after splitting
