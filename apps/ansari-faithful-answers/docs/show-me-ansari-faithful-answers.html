What the code does

Image permission and external-link confirmation are different controls. The stack manages content policy and answer-scoped outcomes; the host decides how an allowed external navigation is confirmed.
Fonts before answers
Kitab Regular and Bold are embedded as bytes and loaded through FontFace. Font readiness has its own failure sentence; no device font is silently substituted for an answer.
Reading follows context
readingProfile comes from the stack. Ansari maps host colors, reading tokens and direction without changing answer data or applying a second root scale.
Attribution stays in the answer
The card renders the full answer once. Ansari watches the rendered closing block to style the attribution; the optional framework credit is separate.

Four lifecycles meet at one card
A server release, a host catalog, a request and an embedded view each have a different owner and lifetime. Keeping them distinct explains refreshes, retries and teardown.
01 · Release
Build & serve
Install exact packages, build artifacts, configure a named target, start the application and prepare immutable view bytes.
02 · Host catalog
Discover & refresh
Register an MCP endpoint and discover its tool and UI association. After a release, verify the host sees the current resource identity.
03 · Request
Invoke & finish
Send a question, call the API, return one full result and release the per-request server lifetime. Calls remain independent.
04 · View
Mount & retire
Connect the bridge, wait for fonts, present the latest result and apply host context. Teardown releases owned browser resources.
What this walkthrough establishes
It explains checked application source, using real names and exact excerpts. The interactive diagrams and card examples are synthetic and make no network requests.
  • Runtime and view composition are grounded in the complete application source of app 0.16.5 as it is committed in this folder.
  • SAGA 0.7.6-rc.1 is installed from the public npm registry as one exact release; the root and application lockfiles record its registry integrity.
  • This document is a fresh explanation of the full architecture, not a summary of changes from an earlier version.
What must be verified in a host
  • A real tool invocation and an actual embedded answer card.
  • Matching application revision, SDK identity and served resource bytes.
  • Fonts, language direction, attribution, sizing and the relevant consent interactions.
  • First-load success distinguished from recovery after Retry.
Rendering inside ChatGPT, Claude and Alexa+ is a separate host acceptance. Neither this document nor this repository’s automated checks establish it.
Read the source offline
Each path links to its exact source commit on GitHub. The embedded source remains available offline through “Read embedded source”.
